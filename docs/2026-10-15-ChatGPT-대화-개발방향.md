#### 가족 발명소 아이디어 도우미 — 개발 착수

##### 프로젝트 목적

2026년 10월 24일 가족 발명소 행사에서 보호자 7명이 학교 공용 iPad로 사용하는 AI 아이디어 도우미 웹앱을 개발한다.

학생이 먼저 생활 속 불편을 찾고, 보호자가 질문으로 도운 다음, 그래도 막힐 때 AI가 3D펜 제작 아이디어 3가지를 제안하는 도구다.

##### 개발 환경

- 프로젝트 경로: `C:\dev\family-invention-helper`
- 별도 Git 저장소
- 배포: Vercel
- AI: Upstage Solar API
- API 키: Vercel 환경변수
- 기존 Cloudflare Worker `sticker-wall-ai`는 수정하지 않는다.

##### 필수 기능

1. 불편 입력칸과 예시 버튼 4개
2. 발명품 아이디어 카드 3장
3. 각 카드에 이름, 해결할 불편, 부품(최대 3개), 모양, 조립 방법 표시
4. 다시 묻기: 더 간단하게 / 부품 2개로 / 다른 아이디어
5. iPad 9세대 Safari 대응
6. 로그인 없는 사용
7. 개인정보 입력 금지 안내
8. API 오류 또는 지연 시 예비 카드 표시
9. 서버 측 API 키 보호, 입력 검증, 요청 제한, 행사 종료 후 API 비활성화

##### AI 답변 조건

- 초등학교 3학년이 이해할 수 있는 문장
- 손바닥 크기, 약 10cm 이내
- 부품 3개 이내
- 평면 부품을 그려 세우고 붙이는 방식
- 실제 3D펜으로 짧은 시간에 제작 가능
- 위험한 물건, 전기·불·칼 관련 물건, 식품 용기 제외
- 구조화된 JSON 응답을 검증한 뒤 화면에 표시

##### 작업 원칙

- 우선 로컬 MVP부터 구현한다.
- 기술 스택은 가장 단순한 구성을 선택하고 이유를 설명한다.
- 인증 없는 공개 API의 남용 방지 방안을 설계한다.
- API 키나 비밀값을 코드, Git, 로그에 남기지 않는다.
- GitHub 저장소 생성 및 Vercel 배포는 별도 승인 후 진행한다.
- 불필요한 DB, 로그인, 채팅, 이미지 생성 기능은 만들지 않는다.

##### 첫 번째 작업

1. 프로젝트 디렉터리와 최소 파일 구조 제안
2. PRD 기준 구현 단계 정리
3. 로컬에서 실행 가능한 첫 화면 구현
4. 실행 방법과 테스트 결과 보고

첫 화면이 확인된 후 Solar API 연동을 진행한다.

### 6. 수업 준비에서 더 중요한 점

첨부 운영안에서 가장 주의할 부분은 학생이 아이디어를 정하는 시간이 12분 정도밖에 없다는 점입니다. 이 시간에 보호자 질문, AI 카드 확인, 발명품 선택, 스케치까지 진행해야 합니다.

따라서 웹앱의 성공 기준은 카드가 화려하게 보이는 것이 아니라, 보호자가 입력부터 아이디어 확인까지 빠르게 끝낼 수 있는지입니다.

또한 웹앱 개발과 별개로 3D펜 기종과 필라멘트 종류를 조기에 확정해야 합니다. 여름 캠프 자료는 고온형 PLA를 기준으로 작성되었으므로, 이번 기종이 달라지면 안전 안내도 수정해야 합니다.

## 대화 2

현재 **가족 발명소 아이디어 도우미**는 기능을 크게 만들기보다, 행사 당일 7가족이 아이패드에서 빠르게 쓰는 **소형 웹앱**으로 보는 것이 맞습니다. PRD에서도 로그인·회원가입·사용 기록 저장·자유 대화형 채팅·이미지 생성은 만들지 않는 것으로 정리되어 있고, 핵심은 `불편 입력 → AI 아이디어 카드 3장 → 다시 묻기`입니다. 가족발명소_아이디어도우미_PRD

| 구분 | 제안 | 이유 |
| --- | --- | --- |
| **프론트엔드** | React + Next.js | Vercel 배포와 서버 API를 한 프로젝트에서 관리하기 쉬움 |
| **백엔드** | Next.js API Route / Route Handler | Solar API 키를 브라우저에 노출하지 않고 서버에서 호출 |
| **AI** | Upstage Solar API | 현재 계획에서 이미 사용할 모델/API로 확정 |
| **데이터베이스** | **사용하지 않음** | 사용자·기록·로그 저장이 MVP에 필요하지 않음 |
| **호스팅** | Vercel | 웹페이지와 API를 한 곳에서 운영 |
| **소스 관리** | Git + GitHub private repository | 코드 버전 관리와 배포 연결 |
| **디자인** | 모바일·태블릿 우선, 카드형 UI | 학교 iPad 9세대 Safari 사용이 주 환경 |
| **인증** | 로그인 없음 | 행사 중 계정 문제를 없애기 위해 |
| **보안** | Vercel 환경변수 + 서버 입력 검증 + rate limit | Solar API 키와 비용 보호 |
| **장애 대비** | 정적 예비 카드 | API 실패·지연 시에도 수업 계속 진행 |

PRD의 실제 사용 환경도 **보호자가 학교 공용 iPad 9세대 Safari에서 사용하고, 동시 사용은 최대 7팀과 교사 시연 1대**입니다. 그래서 데스크톱 서비스처럼 복잡한 구조보다는 태블릿 한 화면에서 바로 이해되는 UI가 중요합니다. 가족발명소_아이디어도우미_PRD

### Rate Limit

여기에는 약간의 판단이 필요합니다.

행사 규모가

```text
7가족
+
교사 1명
```

뿐이라 복잡한 rate-limit 시스템까지 만드는 것은 과합니다.

예를 들어

```text
한 기기
10초에 1번

전체
1분에 30회
```

정도면 충분합니다.

다만 Vercel 서버리스는 단순 메모리 카운터가 안정적이지 않기 때문에 MVP에서는 다음 두 단계 중 하나가 좋습니다.

**1차 MVP**

```text
입력 제한
+
프론트 버튼 재요청 지연
+
간단한 서버 요청 제한
```

행사 후 계속 공개해서 쓰게 된다면 그때 Redis/Vercel KV 같은 외부 저장소를 이용한 제대로 된 rate limit을 붙이면 됩니다.

즉 **DB를 rate limit 때문에 도입하지는 않겠습니다.**
